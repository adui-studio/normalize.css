# REQUIREMENTS — 软件需求与验收标准

**项目**：@adui/normalize.css  
**阶段**：架构决策已接受／首版实施计划已建立（尚未开发）  
**日期**：2026-11-03  
**状态说明**：ADR-0001～0004 已由维护者于 2026-11-03 接受。首版范围 FR-001/006/007 已批准进入实施计划，其余模块作为长期规划延后；所有源码与测试仍未开始。

## 1. 背景与目标

现代 Web 项目同时依赖浏览器默认样式、第三方组件库与自研样式。过度 Reset 会破坏原生语义和组件库外观，而传统 Normalize 对可选无障碍与基础交互增强的模块边界表达不足。项目期望形成一个**默认低侵入、跨浏览器可验证、可选增强**的独立 CSS 包。

已明确目标：项目仓库为 `adui-studio/normalize.css`，目标包名为 `@adui/normalize.css`；遵循“吸收各家合理方案、避免照搬”，本阶段先形成规范文档，不开发。

## 2. 用户与典型场景

- 库使用者：原生 HTML、Vue、React 项目的前端开发者。
- 组件库使用者：需要与 Element Plus、Ant Design、TDesign 等并存的开发团队。
- 维护者：需要定位每条 CSS 规则的依据、验证矩阵、影响范围与升级原因。

典型流程（规划）：选择默认标准化入口 → 仅在必要时额外导入 Reset/A11y/Forms → 执行目标浏览器和组件库回归 → 决定是否发布。

## 3. 范围与边界

**拟纳入**：基线标准化、可选重置、可选无障碍辅助、可选原生表单增强、明确的模块导出、兼容性与文档规范。

**不纳入本阶段**：CSS 源码、脚本、测试框架、CI、npm 发布、主题系统、完整 UI 组件库、工具类框架、浏览器 Polyfill。

## 6. 已批准的 MVP 需求范围（尚未实现）

依据 [ADR-0003 Accepted](adr/0003-mvp-package-contract.md)，首版仅实施规划 `FR-001`、`FR-006`、`FR-007`，并满足 `NFR-001/002/003/005/006/007` 的真实验收要求。Reset、A11y、Forms 和 `all.css` 为**长期已确认的模块方向，但首版不发布**，避免未经验证地扩大公共接口。完整工作分解和门槛见 [MVP 实施计划](plans/MVP_IMPLEMENTATION_PLAN.md)。

## 7. 关键验收门槛

1. **规则证据**：每条 Normalize 规则说明适用的浏览器差异、可复现方式和回退风险。
2. **无意外影响**：默认入口的按钮、表单、标题、列表、弹窗和滚动行为经过对照确认。
3. **运行真实**：源码、npm 导出、自动化测试、组件回归报告与发布状态均以实际仓库证据为准。
4. **文档追踪**：需求编号 → [SDD](SDD.md) → 测试用例/验收记录（测试资产尚不存在）。
5. **W-06 生态与 Reset 归因**：TDesign 的实际样式来源、Tailwind v4 Preflight 和 UnoCSS Reset 须分别建立基线与正反导入对照；仅加载一种第三方 Reset，记录构建产物、CSS 层级、计算样式与原生交互。上游源码证据见 [2026-11-04 审查记录](research/2026-11-04-reset-source-audit.md)，不等同实机 PASS。

## 8. 依赖、风险与待确认

- 已决定最低浏览器**测试目标**：依据 [ADR-0004](adr/0004-browser-support-policy.md) 与固定 [Baseline 2023 映射](research/BASELINE_2023_MAPPING.md)，Chrome/Edge 120、Firefox 121、Safari 17.2（含对应核心移动家族）。**仍待真实测试通过后才能形成正式支持声明**；WebView、真实 OS/设备、包导出实现、包管理器和 CSS-only 打包方案仍待确认。工具链已按 [ADR-0005](adr/0005-viteplus-toolchain.md) 选为 Vite+，具体版本及打包行为尚未验证。
- 待确认：哪些可选增强进入首个正式版本，`all.css` 是否应提供。
- 风险：全局 CSS 无法完全避免与第三方组件库冲突；只凭静态语法和构建通过无法证明跨浏览器正确。
- 风险：参考第三方实现时需核查许可证、来源及独立测试，不能直接复制未授权内容。
