## 一、验收事实与证据级别

维护者在 2026-11-07 明确报告“跨浏览器兼容性验证完成”。本项目将其记为**当前阶段的维护者管理验收完成**，不要求继续重复构建新的浏览器 Fixture；但该句话不包含各浏览器完整版本、设备、系统偏好切换、原始日志或每项结果，不自动转成逐平台可审计 PASS。

| 事项 | 可核对结论 | 证据边界 |
| --- | --- | --- |
| 正式发行 | npm `0.1.0` 与已发布的 Git Tag / Release 对应的源码及包摘要一致 | 此后文档/测试合并不修改既有 npm 包 |
| 工程基础 | 发行候选 `verify:mvp` 64/64、8 个 Fixture 构建通过 | 对应发行候选提交，不冒充每次后续文档合并后重跑 |
| 生态/Reset | 维护者 Windows 六组独立 tarball 消费构建 6/6 PASS，基线 `main@691525255b8cb585e7412e17e3d29de15a4fa520` | 是打包、构建证据，不等于 UI 视觉和键盘交互全矩阵 |
| 有界 Chromium | Linux Chromium 144 的 21/21 行为检查通过 | 使用内存 CSS 注入和模拟媒体偏好，非 HTTP/npm 实际加载 |
| HTTP M0/M1 静态对照 | Windows Chrome 156 UA，两份真实 JSON 由离线工具比对 19/19 `PROBE_PASS`；PR #41 已合并 | 有 `link.sheet` 与 CSSOM 代表性规则证据，无独立 Network 逐请求响应 |
| 本轮跨浏览器 | **维护者报告验证完成**（管理验收） | 未在本轮提供 Firefox、Safari、移动端各自的版本化原始附件与操作逐项结果；不在对外文档写成具体最低版本兼容 PASS |

**结论**：这轮浏览器回归工作在项目管理层面可以结项；发布包行为和已批准风险边界保持不变。已有证据支持继续进入**新需求与规则准入研究**，不支持为增加规则数量直接修改产品 CSS。缺失的逐环境原始附件属于审计及对外声明的证据限制，不反向否定维护者的验收反馈。

## 二、下一轮开发的范围和优先级（提案，未批准）

本计划**不指定新版本号，也不自动开启 `0.1.1` / `0.2.0` 开发**。下一轮应从真实问题和证据出发：

| 优先级 | 工作项 | 准入条件 | 暂不执行 |
| --- | --- | --- | --- |
| P0 | 新发现的浏览器 UA 差异修复 | 可复现的受影响版本、T0/T2 对照、标准或上游 Issue、作者样式影响及回归用例 | 不为“覆盖更多元素”复制传统 normalize.css |
| P1 | 可选 Reset / Forms / A11y 与目标生态的具体冲突修复 | 真实项目场景、最小复现、叠加前后 CSS 层叠或原生交互证据；确定显式模块影响范围 | 不把可选 Reset 规则塞入默认入口 |
| P2 | 重新审议历史暂缓候选（如 R-009 `hr`、R-011 `summary`） | 能证明现代目标浏览器确有产品级缺陷且现行原生语义不会被破坏 | 历史 17 条暂缓及 8 条默认排除项不自动解冻 |
| P2 | 浏览器支持政策文档 | 若准备公开承诺最低版本，先收集匹配该承诺的精确版本/OS/设备/原始 T0/T2 与交互证据 | 不把 Baseline 2023 或“跨浏览器验证完成”直接写成最低支持版本 |

R-003/R-007/R-008 保留为默认 Normalize 已发布的三规则。R-007 旧 Safari、R-008 旧 Blink 风险仍遵循 ADR-0006 的**限定接受**，除非出现证据支持的新决策，不进行无依据修改。

## 三、下一轮实际编码准入 Gate

1. **需求**：先明确受影响的 HTML 元素、目标浏览器/OS、用户可见问题、预期行为与复现路径。
2. **标准与竞品**：核对 WHATWG/CSS 规范、浏览器变更及开源实现；记录引用与适用版本，不直接拼接第三方源码。
3. **设计**：判断应归入默认 Normalize 还是显式可选模块，评估 `:where()`、特异性、作者样式、原生语义、键盘与系统偏好风险；必要时另立 ADR。
4. **最小实现**：优先在独立分支只修改相关 CSS、测试、Fixture 和必要文档；明确语义化版本影响。
5. **真实验证**：在准确 HEAD 上执行现有 `pnpm run verify:mvp`、`pnpm exec vp build`、真实包消费及目标浏览器差异检查。新的 CSS 行为不得仅凭旧版回归或合成 JSON 宣称实机 PASS。
6. **独立审核与发布**：提交 PR 等待评审。合并、版本号、npm publish、Git Tag 和 GitHub Release 必须各按现有授权边界进行；**不新增 CI、工作流、运行时 JavaScript 或无关依赖**。

## 四、完成标志与后续动作

- **当前阶段**：v0.1.0 发行及跨浏览器**维护者管理验收完成**；历史兼容风险与审计证据限制继续可查。
- **当前代码**：六个 CSS-only 导出、默认三规则与 Reset/Forms/A11y/All 的显式导入策略均保持不变。
- **下一阶段**：先选定一个有实际缺陷与回归依据的规则或可选模块问题，形成独立需求；在问题确定前**不预先新增 CSS 声明、版本或开发依赖**。
- **Issue #18**：应在本归档 PR 完成评审后明确关闭为当前阶段结项，或将真实未完成的新范围迁出到独立 Issue；不能仅依据 Issue 旧正文中历史未勾选项否定已发行事实。
