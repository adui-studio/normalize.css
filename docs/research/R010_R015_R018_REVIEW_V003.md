# 0.0.3 · R-010、R-015、R-018 规则准入复审

**日期**：2026-11-05  
**关联**：[Issue #22](https://github.com/adui-studio/normalize.css/issues/22) · [Issue #18](https://github.com/adui-studio/normalize.css/issues/18)  
**研究基线**：`main@73073b7fb6ed85c1e1884bbc24eec7427f3235c3`，工作包版本 `0.0.3`（未发布）。  
**事实分级**：S = HTML/CSS 标准或编辑草案；U = 厂商/MDN 兼容资料；T = 本项目真实浏览器/设备执行结果。**本轮只有 S/U 与仓库已有 Fixture 静态核对，未新增这三条规则的 T 级对照数据。**

## 一、推荐准入结论

| 规则      | 评审对象                                 | 标准/平台事实                                                                                                 | 侵入性与风险                                                                                             | 本阶段建议                                                           |
| --------- | ---------------------------------------- | ------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------- |
| **R-010** | `progress` 垂直对齐                      | WHATWG 建议原生进度控件 `appearance: auto`、`inline-block`、`vertical-align: -0.2em`                          | 强制 `baseline`、`middle` 等会改变原生控件与文字的布局，也可能干扰应用自定义进度条                       | **继续暂缓，不进入默认 Normalize**；发现目标 UA 确切差异时再重开     |
| **R-015** | `input[type=file]::file-selector-button` | CSS Pseudo-Elements Level 4 已定义标准伪元素；MDN 标记 Baseline、广泛可用，2021-04 起主流浏览器支持           | 全局修改字体、边框或 `appearance` 属外观 Reset/Forms；回退到旧 WebKit 前缀需特定历史目标与缺陷依据       | **继续暂缓默认模块**；组件需求优先走独立 Forms 评审                  |
| **R-018** | 关闭状态的 `dialog`                      | WHATWG 建议 `dialog:not([open]) { display: none; }`，同时定义 `dialog:popover-open` 与 `[popover]` 的状态样式 | 作者级 `display:none` 可能盖过原生 `showModal`/popover 状态；覆盖 top layer、焦点和 Esc 原生语义的风险高 | **继续暂缓，不引入兜底隐藏规则**；只对可复现 UA 异常提供范围受限补丁 |

三项均**未证明“为默认 Normalize 提供必要的当前浏览器差异修正”**。这是**新一轮研究建议，待维护者审核**，不是永远排除，也不改变既有 36 条规则分类（已实现 3、继续暂缓 17、可选设计 8、排除默认 8）。

## 二、R-010：`progress` 的垂直对齐

- S：现行 [WHATWG HTML Rendering §15.5.15](https://html.spec.whatwg.org/multipage/rendering.html#the-progress-element) 将 `progress` 描述为原生 UI 控件，建议原生尺寸约 `1em × 10em`，`vertical-align: -0.2em`，并要求表现符合平台习惯；这里是**建议默认呈现**，不是让第三方库全局注入等同值。
- S：[`vertical-align` 参考](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/vertical-align) 解释负长度对行内盒的基线偏移；`vertical-align: baseline` 不等于修复跨平台差异。
- 仓库既有 [R-010 首轮证据](RULE_EVIDENCE_BATCH1.md) 已因此将旧式 Normalize 的 `progress { vertical-align: baseline; }` 降为暂缓；目前没有新的 UA/OS 实测证据推翻这一决定。
- 核验场景 F-002：**同一字体/行高上下文**的文字 + 原生确定进度 `<progress value="0.4" max="1">`，以及无 `value` 的不确定进度；分别观察 `getComputedStyle(progress).verticalAlign`、盒尺寸、视觉基线和动画/高对比度表现。另设作者显式 `vertical-align: middle` 的对照，确保默认库不覆盖作者意图。

**重开条件**：明确目标浏览器/OS、原生 T0 错误与可复现最小页面，证明候选 T1 修复确有必要，且未改变其他平台原生体验；不把跨平台视觉本就不同误归因于浏览器缺陷。

## 三、R-015：文件选择按钮与标准伪元素

- S：[CSS Pseudo-Elements Level 4 §5.1](https://drafts.csswg.org/css-pseudo/#file-selector-button-pseudo) 定义 `::file-selector-button` 指向文件上传控件内的按钮，**前提是 UA 实际渲染该按钮**。编辑草案不等于所有目标浏览器行为完全一致。
- U：[MDN `::file-selector-button`](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Selectors/%3A%3Afile-selector-button) 标记 Baseline widely available（2021-04 起），与项目历史 Chrome/Edge 120、Firefox 121、Safari 17.2 的特性支持范围相符。这是 **BCD/文档兼容性依据，不是本仓库的实际设备 PASS**。
- U：同一 MDN 页面说明伪元素本身拥有 UA 默认样式，字体/颜色**不保证继承自 input**。这说明“字体不同”不必然是 Normalize 缺陷，是否统一属产品设计或 Forms 模块选择。
- 仓库原 [表单规则评审](FORM_CONTROLS_REVIEW.md) 已将旧 WebKit 伪元素回退与强制外观重置暂缓，不应仅因浏览器能识别标准伪元素就添加空规则或全局声明。
- 核验场景 F-004：`<label for="upload">上传</label><input id="upload" type="file">`，分别核查单文件与 `multiple`、禁用状态、键盘 Tab/Space/Enter 与文件选择框启动、焦点显示、屏幕阅读器标签；组件库自定义文件上传触发区与原生输入框应分开评估。可在控制台用 `CSS.supports("selector(input[type=file]::file-selector-button)")` **仅检测选择器语法**，不将其冒充按钮外观/交互通过。

**重开条件**：目标 UA 缺失实际标准按钮选择器且明确需要向后兼容、存在可再现问题，并提供不破坏用户外观/组件库和键盘操作的最小修复。若只是统一字体/边框，应明确归类为可选 Forms，而非默认 Normalize。

## 四、R-018：关闭的 `dialog` 与 `popover` 组合状态

- S：[WHATWG HTML Rendering §15.3.3](https://html.spec.whatwg.org/multipage/rendering.html#flow-content-3) 已给出 `dialog:not([open]) { display:none; }` 的 UA 建议，同时包含 `[popover]:not(:popover-open):not(dialog[open]) { display:none; }`、`dialog:popover-open { display:block; }` 和 `dialog:modal` 样式。**不能只摘取第一条再覆盖整个状态机**。
- U：[MDN dialog 元素](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/dialog) 说明未设置 `open` 的原生对话框不可见；模态/非模态的关闭行为、焦点与可访问性语义不同。[`showModal()` 参考](https://developer.mozilla.org/en-US/docs/Web/API/HTMLDialogElement/showModal) 说明模态进入 top layer 并使页面其他内容 inert；这些原生行为不应被 Normalize 的强制 display 声明改写。
- 本仓库 `fixtures/t2-native.html` / `fixtures/t2-package.html` **已有原生 `dialog` 和关闭按钮**，之前 W-06 的 Chrome 156 `showModal()` / Esc 反馈只证明该环境的相应人工子项；不构成此规则对全部浏览器的实测。
- 核验场景 F-005：初始无 `open`、`show()`、`showModal()`、Esc（仅在适用状态）、`<form method="dialog">` 关闭及焦点返回；在支持的 UA 中额外验证兼具 `popover` 属性的 `dialog` 状态，避免强制隐藏打开中的弹层。

**重开条件**：某确切受支持 UA 初始关闭对话框错误可见，且确认不是作者 CSS、polyfill 或 UI 框架造成；补丁必须保留所有打开、popover、top layer、焦点和 Esc 路径。没有证据时，不新增 `dialog:not([open]) { display:none }` 作者级默认规则。

## 五、最小人工验证方案（不修改产品代码）

仓库已有 `vp pack` 与 `vp dev`，但要注意：**当前的 15 点 `tests/t2-evidence.mjs` 只比较字重、等宽字体、缩写与表格，不包括 R-010、R-015、R-018 的逐项自动断言**。因此即便返回 `PROBE_PASS`，也不能说三项已经验证通过。

本次建议先使用人工场景，不将实验样式混入 `src/normalize.css`：

1. **固定环境**：记录浏览器完整版本、OS、设备、测试日期、`git rev-parse HEAD`。运行 `pnpm exec vp pack`、`pnpm exec vp dev`，使用真实打包 CSS；逐次比较有/无本库 CSS 的 T0/T2。旧版浏览器仅在安全隔离的本地测试环境使用。
2. **R-010**：在独立最小本地页面中展示文字、确定和不确定 `progress`、显式作者对齐版本。记录 `verticalAlign`、`getBoundingClientRect()`、视觉截图与作者样式覆盖。若编写单规则 T1，仅在隔离测试页临时使用，不能并入发布 CSS。
3. **R-015**：使用原生 `type=file`、关联 `label`、可选 `multiple` 与禁用状态。手动检查操作系统文件选择窗口、键盘聚焦、按钮样式与控件可访问性。CSS 选择器支持与文件选择操作成功必须**分开记录**。
4. **R-018**：可复用现有 `#t2-dialog`，在 DevTools Console 手动执行 `document.querySelector("#t2-dialog").showModal()`，使用 Esc 或已有 `method="dialog"` 按钮关闭；记录关闭前后 `open`、计算 `display`、焦点及可见状态。对 popover 组合另建立隔离最小页面，避免污染基础 Fixture。
5. **证据格式**：每一规则记录“浏览器/OS/设备 · T0 实际值 · T2 实际值 · 是否有实际缺陷 · T1 修复与副作用（若有） · Network/CSSOM · 交互截图/日志 · 结论”。T0/T2 如果零差异，通常是“无需修复/本环境无可观察差异”，**不是**新增规则必要性的证明。
