# ADR-0001 — CSS 基础策略与可选模块边界

- **状态**：Accepted（2026-11-03，维护者明确同意方案 B）
- **日期**：2026-11-03
- **范围**：默认 CSS 行为、模块职责与层级策略
- **关联需求**：[FR-001 ~ FR-007、NFR-001 ~ NFR-008](../REQUIREMENTS.md)
- **关联设计**：[ARCHITECTURE](../ARCHITECTURE.md) · [SDD](../SDD.md)

## 1. 背景

项目希望自建 `@adui/normalize.css`，吸收 normalize.css、modern-normalize、sanitize.css、browserux.css、Tailwind Preflight、UnoCSS Reset 的合理实践，同时避开过度重置与默认视觉干预。仓库目前只有初始 LICENSE 和文档，尚未形成实现或验证证据。

## 2. 驱动因素

1. 普通项目和既有 UI 组件库都需要稳定、可预测的浏览器基础行为。
2. Normalize 与 Reset 目标不同；将无障碍和交互偏好混入默认 CSS 会增加样式侵入性。
3. 每一条保留规则需要浏览器差异证据、清晰归属与实际测试。
4. 增强能力需要让使用者明确选择，防止工具链叠加多个 Reset。

## 3. 候选方案

| 方案                                                     | 优点                       | 代价/风险                                     |
| -------------------------------------------------------- | -------------------------- | --------------------------------------------- |
| A：纯 Normalize，只有单一入口                            | 简单、侵入性小             | 无法对可选增强提供官方边界                    |
| B：默认 Normalize + 独立可选模块（**已接受的长期方案**） | 默认克制、可扩展、按需使用 | 入口增多，需要严谨的层级和回归测试            |
| C：默认完整 UX 基础层                                    | 开箱即用的更多体验改善     | 与 UI 库/主题系统冲突风险大                   |
| D：直接包装第三方 Reset                                  | 初期成本低                 | 原创价值不足、来源/兼容边界复杂，可能偏离需求 |

## 4. 已接受的架构决策

维护者于 2026-11-03 选择方案 B：默认仅提供浏览器标准化；将 Reset、A11y、Forms 与可选组合入口定义为**待评审**增强模块。任何影响页面主题、根字号、按钮外观、全局滚动条或彻底移除默认间距的行为，不自动进入默认入口。

长期采用“默认 Normalize + 独立可选增强”的架构边界；但**不要求首版同时发布所有模块**。[ADR-0003](0003-mvp-package-contract.md) 已接受首版只提供默认入口的范围。[ADR-0002](0002-cascade-layers.md) 已接受首版默认不内置 `@layer`。

**决策接受不等于已有 CSS 或验证结果**。每条默认规则仍须证明真实浏览器差异；可选模块在后续独立评审实现。

## 5. 理由与预期收益

- 更明确的职责边界；消费者可以只使用最基础的浏览器差异修复。
- 可以在不改变默认入口的情况下增加体验增强。
- 便于按模块归因样式回归，降低维护复杂度。
- CSS 规则和测试可以逐条追踪，不以第三方项目版本更新频率代替质量证据。

## 6. 代价、风险与回退

- 可选入口增加文档/测试/发布维护成本；首版可以延后部分模块。
- `@layer` 改变层级竞争关系，对现有 CSS 具有潜在迁移影响。
- 真实浏览器/组件库测试不足时，不能推断兼容性已达标。
- 如试验表明层级或增强引入不可接受的冲突，优先简化入口和规则，必要时回退为方案 A。

## 7. 决策已接受与实施前提

- **已决定**：方案 B 的长期模块边界，首版范围以 ADR-0003 Accepted 为准。
- **待实施验证**：最低浏览器版本、每条实际修复的必要性、组件库与无障碍回归、CSS 导出是否可用；由 [实施计划](../plans/MVP_IMPLEMENTATION_PLAN.md) 追踪。
- **权限边界**：本次授权为将已评审方案转为 Accepted 与实施计划；未授权直接开始写 CSS、安装依赖或发布。
- 如未来实证要求改变长期架构，另立 ADR 修订，不回写历史结论。
