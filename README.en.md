# @adui/normalize.css

[简体中文](README.md) · **English**

A minimal, evidence-driven CSS Normalize library. It aims to preserve native browser defaults while correcting demonstrated inconsistencies, without runtime JavaScript.

> **Development preview; not published.** The feature branch now contains one Normalize rule (R-003), one CSS root export and a dependency-free static CSS build. The package remains `private: true` at version `0.0.0`. Browser support and UI-framework integration have not completed release validation.

## First implementation

Only R-003 is included in `src/normalize.css`:

```css
b,
strong {
  font-weight: bolder;
}
```

Chrome for Testing 120.0.6099.109 showed four computed-weight differences between the native and candidate pages for `b` and `strong` with parent weights 600/700; the candidate changed 700 to 900. Firefox 121 and Chrome 156 showed no additional computed-weight change. These are limited, observed results—not a full compatibility guarantee.

R-004 deliberately does **not** normalize the font size or font family of `code`, `kbd`, `samp` and `pre`. Browser defaults are retained. Reset, Forms, Accessibility and combined styles are deferred.

## Local build

The maintainer has verified that **`vp pack` supports a direct CSS-only entry** in Vite+ 1.4.0, producing a single CSS asset and no JS. The first CSS-entry `vp build` failed because library mode defaults to `cssCodeSplit: false`, which rejects a raw CSS input. The config now assigns `vp build` to the six local HTML fixtures (`dist-fixtures/`) and **`vp pack` to the CSS package (`dist/normalize.css`)**. Re-test the updated configuration locally before considering it verified.

```sh
vp dev              # Local fixture server
vp build            # HTML fixture preview: dist-fixtures/
vp pack             # CSS-only package asset: dist/normalize.css
vp check
vp test
npm run test:offline
npm run test:package   # After vp pack: real tarball + offline installation
```

The only package export is `@adui/normalize.css` → `./dist/normalize.css`. The intended integration with a bundler that supports CSS package imports is:

```js
import "@adui/normalize.css";
```

This import is **not yet production-verified** in Vite+ and Webpack consumers. Build the CSS before packaging, and do not publish the package without explicit release approval.

The previous Node-copy build and packaging contract passed in a standalone Linux Node.js 22.16.0 environment; the migrated Vite+ configuration has **not** yet been executed with the project's supported Node/Vite+ runtime. Five updated dependency-free Node contract tests passed separately, but this does not verify `vp build` or `vp pack`. The maintainer previously reported 25/25 offline tests passing before this migration.

**Maintainer's latest verified results (before the configuration fix)**: `vp check` passed (55 format, 11 lint), `vp test` passed 6/6, offline Node tests passed 25/25, `vp dev` started, and `vp pack` emitted only `dist-pack/normalize.css`. The corrected split of build/pack outputs has not yet been run on Windows.

**W-04 real package smoke test:** `npm run test:package` uses the actual `dist/normalize.css` generated by `vp pack`, packs it from the full repository into a temporary directory, installs it offline into a separate temporary consumer, verifies `exports`, allowed files, license, README, CSS bytes and unpublished subpaths, then cleans up. This is separate from the normal synthetic `test:offline` suite. The test passed in a representative isolated Node directory, but it has **not** yet been executed against the maintainer's complete Windows checkout, and it does not replace Vite+/Webpack production consumer checks.

## Scope and constraints

- Default Normalize is low-intrusion; no forced root font size, global theme, button reset, general margin reset or `@layer`.
- Exactly one CSS root export. There are no public `/reset.css`, `/forms.css`, `/a11y.css` or `/all.css` exports in the MVP.
- Baseline 2023-derived Chrome/Edge 120, Firefox 121 and Safari 17.2 browser targets are **test targets**, not supported-version claims. Edge, Safari, mobile browsers and component-library regressions remain unverified.
- No CI, no new runtime dependencies, no npm publication.
